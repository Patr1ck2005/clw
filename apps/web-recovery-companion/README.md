# CLW Web Companion 0.6.6

## 监护已经运行的 Edge 对话

这是原网页的轻量失败监护，不需要打开 CLW 或重新接入项目。支持保留当前 Pro 模型，不重贴原工作需求、不切换模型或跳去别的对话。用户已批准：连接等待且公开进度三分钟不变时，可刷新同一原页核对，每条接续链最多两次；正常长思考不因此刷新。不取消 AB、Runner 或已提交的 Job。

1. 在 Edge 打开 `edge://extensions`，打开「开发人员模式」，点「加载解压缩的扩展」，选择本目录 `D:/Dev/Projects/Personal/clw-webcodex/apps/web-recovery-companion`。首次安装需要用户在浏览器中完成，程序不静默安装。
2. 回到原来正在运行的对话，点扩展图标 → **启用当前页监护与失败接续**。启用会在原页注入观察器，不需要刷新或重新发送。只绑定这一个实际标签页及确切 URL。
3. 弹窗打开时每两秒只读刷新本机状态；没有新鲜观察会明确过期。启用成功、观察新鲜、接续已点击、网页已确认新消息分别记录。扩展图标圆点表示有观察，`!` 表示需要处理；暂停或限次用尽时查看具体原因。历史记录不能冒充当前已绑定。

检测最新助手回合中公开的「无法思考／思考失败／生成回复时出错」等明确状态，以及已经停止生成的连接错误。只有当前回合不再生成、输入框空闲、无草稿、在线且网页可识别时，才按 15、45、120 秒退避，各发送一次固定短接续；每条监护链最多三次。普通长思考或没有输出不会触发发送。开始监护时已经存在的旧失败只作为基线，不立即发送。

固定提示：

> 继续原任务。先核对已有成果和在途作业，从未完成处继续，完成当前所有可推进的工作。

输入、停止、切换模型和离开该 URL 优先让给用户，监护暂停；「停止当前页监护」只停止后续监护，不点击网页 Stop，也不停止本地 Job。需要再次监护时，在同一原页明确启用，或由本地 Codex 下发 watch。程序自行刷新后核对原 URL、新文档及原用户回合后恢复观察；人工刷新、浏览器／扩展重启后不默认重启旧监护。原账本、次数和未知发送不因重绑而清空。

断网时先等网络恢复；「连接已中断，正在等待完整答复」是独立等待状态，不是 idle，也不单独授权补发。Stop 同时识别当前 composer 内的 aria-label。只对明确连接等待计无进展时长，活动标题／公开回复变化会重计；草稿、焦点、输入法、离线和人工操作阻止刷新。刷新许可先存盘，最后在原文档内核对人工状态再重载；回执未知不重复刷新。新页仍生成就等，已有正常回复不补发，明确失败才进入短接续。登录、额度、平台拒绝、无法加载对话或浏览器休眠仍可能需处理；不保证平台持续生成或恢复隐藏思考。

## 本地操作员的程序控制（Codex／Claude Code）

控制桥只监听 `127.0.0.1:18946`，无窗口运行，不调用模型，不需要打开 CLW。当前用户已授权本地操作员对已配对扩展登记的全部 ChatGPT 对话进行控制：每个命令明确原 URL、标签与文档，不逐条对话重复申请授权。A/B 所在的 Edge 配置区用独立随机 profile 身份，浏览器重启和扩展更新保留配对，不互相顶掉。

此 CLI 不限定调用方为 Codex，Claude Code 可以直接执行同一入口，无需额外 Sol／Astra 转发。它控制已登记的原页，不负责新建会话或选择模型；需要原生文件／终端工具工作包时，使用现有 [Codex＋Web 启动器](../codex-web-bridge/README.md#让现有-codex-主控派发完整-web-工作包)。

本机执行入口（Python 路径沿本机已有运行时，后台启动须无窗口）：

```powershell
python -B scripts/web_companion_control.py serve
python -B scripts/web_companion_control.py status
python -B scripts/web_companion_control.py pending
python -B scripts/web_companion_control.py approve --peer-id <id> --pairing-nonce <nonce> --allow-chat <原URL>
python -B scripts/web_companion_control.py command --url <原URL> --type inspect --id <唯一UUID> --wait-seconds 5
```

命令支持 `inspect`、`watch`、`unwatch`、`continue`、`send`、`stop_generation`、`reload`、`reload_extension` 与 `approve_tool`。`send` 用 `--text-file` 传入长正文；`continue` 默认使用上面的短接续，也可显式指定正文。`stop_generation` 真正点击网页 Stop，与只停止后续监护的 `unwatch` 区分；两者都不取消本地 Job。`approve_tool` 仅确认原页唯一可见的常规 Local-MCP／B 工具允许卡，不替代登录、验证码或真实平台拒绝；点击、卡片消失、工具实际运行分别核对。重发核对用原 `--id` 和 `receipt --id`，不能换 ID 重做未知发送或确认。

首次旧扩展没有通道时，需要用户在 `edge://extensions` 重新加载一次；之后 Codex 可以通过 `reload_extension` 请求自身更新。更新调用与新实例／版本登记分开核验，不能只凭旧控制连接或点击成功认定已更新。此控制桥本轮已运行，尚未登记新的 Windows 自启动；电脑重启后 Codex可自行沿上述入口无窗口启动，不需要用户再打开 WebCodex 点按钮。

## 数据与兼容

自动监护不请求平台历史或私有聊天 API，不读取 Cookie；只上报回合／进度 SHA256、故障枚举和布尔状态。用户明确通过本地操作员下发 inspect 时，才返回该原页的公开标题、可见模型标签、有界活动、最后用户需求与回复尾部（正文各最多4096字符），另有main公开尾部6000字符和最多16个按钮标签；长文本标截断，不打开模型菜单。回复读取最新用户后的可见正文，编辑器焦点结合真实document焦点，避免后台保留的activeElement冒充人工输入。后台在 `chrome.storage.local` 按 URL SHA256 保存计数和一次性记录；实时 URL／标签绑定及 peer 凭据放在受信任 `chrome.storage.session`，local 另保留随机 profile ID。控制桥的凭据、原命令和回执保存在忽略的 `.local/web-companion-control`，不放进 Git 或普通诊断导出。

用户2026-10-25授权全部并行 Edge Web Pro 每小时巡检与故障恢复，当前巡检登记及结果回 CURRENT。正常长思考、独立计算等待、已交付和人工暂停不接续。明确故障才刷新同一原页并重新核对；仍卡住时停止网页生成，再短接续，保留原模型和本地Job。仅对显式inspect、且Edge窗口未聚焦的冻结页，临时激活目标标签以解除冻结，读完或超时后还原原选中标签；不聚焦窗口、不刷新网页。用户自己切换或聚焦后不抢回；前台窗口、丢弃／加载页及未能读回的页面明确记为未知。元数据轮询不唤醒页面，只读检查超时不能阻塞其他页。

原 CLW 已登记任务入口保留在高级折叠区，沿原 Session／request／claim 合同及原低成本测试限制运行，与新监护不能同时派发同一页。旧 WEB_RECOVERY 的配码、任务登记不适用于新模式。复用同一个扩展，新增的只有本机程序控制桥，没有新依赖或 AI 监督回合。

程序回归与空数据浏览器验证不等于用户真实页面验收。当前版本是否已经在用户 Edge 中加载、目标页面是否已有新鲜观察，以实际扩展状态为准。

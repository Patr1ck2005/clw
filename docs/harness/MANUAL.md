# 手动使用 CLW

只需桌面「CLW 工作区」。不需要另开 WebCodex Desktop，也不需要让另一个 Codex 对话一直盯着它。

**主程序更新后加载新版本：**点击侧栏下方独立的「退出并保留现场」，等应用退出后再从桌面打开。右上角「×」只收进托盘，此时点击快捷方式仍会打开原进程；刷新对话网页也不会加载 CLW 的新代码。原任务、登录与已保存内容保留，暂停任务不会因重启自动恢复。不要为加载更新重复新建任务。只有界面资源变更时，可由正式应用控制接口重载本地界面，保留当前网页及后台执行。

普通退出先暂停后续自动发送，等待当前真实网页回合及应用内 Codex 回合结束，再保存关闭工作区。独立后台计算和本地 Codex 终端继续运行，不要求所有本地任务空闲。未完成目标、已送达但等待结果的请求和原写入预约会保留，不要求全部业务成功。退出中显示正在核对及具体任务/Job停点；重复点击等待同一次关闭，原关闭回执未知时只核对原操作。若owner已退出而记录保存失败，可接续保存，不再关闭一次。普通退出的实际装载与旧版本缺口看 [CURRENT](../../CURRENT.md)，不能用更新后的手册推定正在运行的旧进程已具备此行为。

「暂停全队」用于严格维护，停止新派发，已送达回合继续完成。等待期间可点「撤回全队暂停」继续原有工作；已停稳后点「恢复全队」。撤回等待按原维护身份核对，不结清未知接入、发送或执行，不清除单独暂停。维护退出还须原维护停稳证明；普通退出不会替它核销未结业务。

页面以连续工作记录和底部输入框为主，左侧按项目组织任务；目标、待发补充和当前动作放在输入区附近，设置与诊断按需展开。首次发送显示原要求、送达状态与当前进展；「展开要求」读取完整原文。纯 Web 与 Codex＋Web 共用记录和工具活动的视觉结构，账号、任务归属及执行方式保持各自真实含义。等待反馈表示操作正在处理，实际送达和完成仍看原回执。

侧栏下方将「工作方式」与可折叠的「账号与连接」「工作区」分开。账号组包含登录、Pro用量及连接设置；工作区组包含已关闭对话、外观及项目入口。箭头和缩进标明所属层级，展开状态随刷新保留；「后台运行」「退出并保留现场」始终独立显示。

本轮结果保存、整个 Goal 交付和后续发送暂停是不同状态。网页状态读取超时单独提示，不覆盖已保存结果；没有待续工作时不显示恢复按钮。暂停中的新输入是本机草稿，明确解除暂停后仍需发送；工作中的补充只排入下一轮。本轮用时从确认送达开始，需求历时还包含排队、暂停和等待，不是整个 Goal 的累计工作时长。

目标条直接提供「暂停目标／继续目标」和「关闭目标」。暂停只控制后续自动推进；关闭结束该 Goal 的追求，保留原要求、对话、成果和未知发送，可从输入框「＋」重新设置目标。真实网页正在生成且输入为空时，输入框右侧显示方形停止键；确认后停止主控与协作者的网页生成，独立本地 Job 继续。左侧任务的「×」是移出列表并保留现场，可从已关闭列表找回。

新记录自动显示；当你主动向上阅读旧内容时保留位置，并提供回到最新的入口。工作记录支持 Markdown 和离线数学公式，例如 `$E=mc^2$` 与 `$$\int_0^1 x^2\,dx=\frac13$$`，所需脚本和字体随应用提供。长回复先显示预览，展开或复制时读取完整正文；切换任务不会把另一个任务的迟到内容放进当前对话。

Codex 可通过[应用控制接口](APP_CONTROL.md)直接读取状态、切换视图、核对原操作、重载界面和正常退出，无需模拟鼠标操作。重载界面保留网页与执行代理；普通暂停只停止后续自动派发，当前网页、工具调用和结果回收继续。「停止网页生成」是单独的中断动作。

纯 Web 的「对话网页」可直接输入、发送、选择模型和切换对话，不必使用 CLW 输入框。在原网页按键或点击后，CLW 暂停该任务后续自动发送，已送达回合与结果保存继续；单纯滚动阅读不会暂停。继续手动聊天无需返回管理界面；需要重新启用自动化时使用现有「恢复」操作，新的网页操作仍优先。网页模型不同于任务保存值时只提示核对，不自动改回。

对话网页的刷新按钮位于上方页签旁，F5／Ctrl+R 使用同一入口，刷新当前网页。手动切换的对话与浏览位置会保留，刷新、后台观察和重开不会因此擅自返回旧对话；旧任务、消息与回执身份仍独立保留。正在生成、有草稿或正在受理发送时不会重载。普通 HTTPS 外链在你点击时由系统浏览器打开，后台脚本不会自行打开浏览器；登录弹窗仍使用原账号分区。只读网页检查最多等待8秒，同一未返回的底层读取只保留一份，检查卡住不会永久占用任务操作。

## 本机目录访问授权

2026-10-18 用户明确批准本机 A／B 的 Local-MCP 不设开发目录白名单，且长期保留，只有用户明确撤回时才收窄。共享 Runner 已开启 `policy.allow_cwd_anywhere=true`，并在 `allowed_roots` 显式加入 C／D／E／F 盘根；原白名单保留。普通本地目录可按任务直接登记、读写，包括 Downloads 和以后新增的目录，无需逐目录追加白名单。此授权属于本机个人环境，不改变免费预览版其他用户的首次授权默认值，也不自动启动任何业务。

修改通过 `runner_config_check` 校验、以原 generation 调用 `runner_config_reload` 热加载，无需重启 AB 或 Runner；当前生效身份和证明见 [CURRENT](../../CURRENT.md)。目录授权不等于读取全部磁盘，实际工作仍按用户当期目标选择文件；Windows 本身的文件权限、平台确认和具体任务的只读／写入分工分别保留。

设置保存在共享 Runner 原 `runner.toml`，不随模型回合结束清除。当前 Windows 登录和桌面恢复共用 `recover_local_mcp.ps1 → webcodex_backend.prepare → ensure`，沿原 `backend-launch.json` 引用同一配置启动；A／B 都接入同一个 Union 和 Runner，权限没有两份独立副本。开机恢复不重新生成此文件；以后维护、重新配对或迁入新版时也须继承本机这一明确选择，不能用新用户默认值覆盖。若用户主动更换连接或配置，先保留本机授权，再沿正式校验与热加载核实。

大文本用 `read_files` 的行范围与原续读游标分段阅读；`project_artifact` 的附件检查大小限制是传输边界，不代表目录被拒。Downloads 已登记为 `user-downloads`；截图中的文件名实际为 `ChatGPT_2026_10_18__0323.md`，日期与时间之间有两个下划线。

## CLW 工具确认默认允许

用户于2026-10-25确认：**使用CLW即代表完整批准当前任务内的工具执行、MCP工具确认和返回文件确认**。A/B、纯Web和Codex＋Web沿同一规则自动处理，不逐次询问。识别并允许原卡后核对工具进展，不靠重发任务跨过确认；过程及回执可查看。当前权限默认从已有owner策略和原生autoApproveToolCalls生效；中文、英文及内嵌确认卡均须覆盖。

确认优先使用“始终允许”，没有该按钮时使用一次允许；同一原任务的多卡顺序处理，已点击或未知回执不重复点击。长需求收起不改变原消息身份。确认适配器可通过原在线更新入口加载，保留正在工作的网页与执行器；不要求先退出应用，实际装载看CURRENT与正式更新回执。

人工暂停、只读要求和本包写域属于任务指令，仍按原要求执行；默认批准不恢复旧的暂停业务，也不把发送未知当作可以重发。

## 选一种工作方式

纯 Web 普通对话在一轮回复保存后结束；开启「目标」后，未完成内容才自动接续。默认不限时长和发送次数，保存目标本身不发送、不恢复暂停。旧的手动验收目标保留原模式：先记录验收，再明确开始下一包。本地发送预算包含主控及协作者的网页发送，不是工作包数或平台官方额度；Codex＋Web与本地 Codex仍沿各自入口执行。实际装载状态看 [CURRENT](../../CURRENT.md)。

下一包已准备、发送回执未知时，界面只核对原操作，不另发新键。明确未发送或已拒绝时，可在同一入口「撤销待发的下一包」；撤销由原账本核对，目标、验收、额度及错误保留。结果未知的执行不能撤销或用新请求替代。

两个游戏后续自动派包已按用户最新要求暂停，当前包保持，用户负责验收和发放后续额度。数学仍暂停，旧 Codex 监督未恢复。历史自动目标可用 `python scripts/harness_goal_watch.py status` 查看；人工验收目标不能用旧 watcher 的 `resume` 接管。历史数学持续目标的验收记录仍见[原报告](../../evidence/MATH-GOAL-20260929/REPORT.md)，不作为当前运行状态。

| 你的需求 | 打开哪里 | 目标发在哪里 |
|---|---|---|
| 自己直接使用网页模型开发，沿用 Codex 文件/命令工具 | 左下工作方式「Codex＋Web」→「新建任务」 | 打开的专用 Codex 终端 |
| 纯 Web 单对话或按需启用协作 | 左下工作方式「纯 Web」→「新建任务」 | 完整目标与接入一次发送，后续在「工作记录」继续 |
| 只看已有工作的网页和回执 | 选择原任务 →「对话网页」或「工作记录」 | 查看无需发送消息 |

Codex 登录账号与网页账号独立。先确认 CLW 设置中的实际网页账号；已有任务保留原账号，不通过换账号恢复旧执行。Chat Pro 额度卡与 Codex 额度分开。

「账号与连接」→「Pro 用量与可用性」只显示本机已保存的统计、模型观察与手动限制记录，不再联网更新。历史卡保留原采集区间和时间，旧完整结果可以查看，但不称为当前滚动七天的统计；没有完整结果时显示未知及已有读取缺口。模型不明的回复不计作 Pro。网页可读历史不等于官方扣额账本，不据此推算余额；临时、已删除、未完成及列表未返回的归档记录不计。

用户主要在 Edge 手动进行网页与 Web MCP 工作，同账号的辅助读取也可能触及网页服务限制。为避免统计占用额外请求，历史更新、统计验证窗口及辅助模型菜单核对已停用；旧程序入口同样返回禁用，不打开网页、不重试。用量页的手动记录和清除仅保存到本机，旧限流或验证错误标为上次采集，不要求用户再次验证。账号信誉是否变化没有可核实的公开判断依据，不能由一次限流推断。

正常任务的模型选择、账号登录及实际工作继续沿原入口；停用辅助统计不停止 Web MCP。维护或装载界面不得关闭、切换用户的 Edge 或抢走焦点；当前正在使用的 AB、Runner 与独立 Job 不为用量页更新而重启。实际源码装载及原实例身份看 [CURRENT](../../CURRENT.md)。

左下工作方式只用于切换模式；「账号与连接」和「工作区」分别展开其子项，展开状态会保留。后台运行与退出固定在底部，不随分组收起。

## Codex＋Web：直接开始一个完整工作包

1. 点左下工作方式「Codex＋Web」，再点左侧「新建任务」。
2. 在「启动与连接设置」确认网页账号、本机连接、模型和工作目录。必要的开发/研究选 Pro；接入或流程测试选 Extra High。未就绪时看具体提示，不重复创建工作包。
3. 点「打开 Codex＋Web」。在专用终端输入完整目标，给出需求文档、可写范围、完成条件和交接位置。这个终端直接使用网页模型，不需要普通 Codex 主控持续参与。
4. 回到 CLW 的「任务总览」。每张卡片是一项 Codex 任务；打开后进入工作记录，和纯 Web 共用状态栏、消息样式及工具活动展示。记录显示已保存的网页最终回复，保留 Markdown 原文；旧回合缺少对应原文时明确提示查看原网页，不拿别的回合补齐。历史回合折叠在下方；「对话网页」始终查看同一任务的原网页。
5. 补充、停止、继续在原 Codex 终端操作。结束后可用「在 Codex 接续」打开同一任务；按钮本身不发送消息。不要在已结束的原生网页回合里手动发“继续”，它的工具执行身份已经结束。

两种工作方式共享目录占用检查。一个任务覆盖整个 `Games` 时，其中 TENET 等项目的其他写者也可能与它冲突。当前任务显示“本轮完成”只表示自己的回合结束，不代表整个目录空闲。新版未发送提示会给出具体 Codex＋Web 工作包和目录；先查看该原任务，勿重复新建或删账本。排队任务轮到执行时会重新核对当前连接和原账号；连接/账号变化且无法核验时保留未发送记录，不擅自迁移或重放。

当前没有“工作包完成后自动唤醒指定桌面 Codex 主控”的功能。可以让后台工作自己运行，稍后手动查看结果；不必让任何模型反复查询。回合结束后仍要检查文件和验证记录，不能只看绿色状态或退出码。

## 列表不会替你操作任务

- **任务总览：** 当前未归档任务；一项任务不会因有多个回合而占多张卡片。
- **左侧任务：** 与总览使用相同搜索和归档范围；点击后进入该任务详情。返回总览不会清空搜索，搜索也不会删掉已打开任务的历史。
- **已归档：** 整理已停止或已结束的旧任务，随时可移回。归档只保存本机列表偏好，不删除 ChatGPT 对话、成果或执行账本；运行中或原执行未知的任务不能归档，新活动会重新显示。
- **工作记录／对话网页：** 同一任务的两种查看方式，不是两个任务。切换纯 Web 与 Codex＋Web 也不会停止正在执行的工作。

旧故障与诊断记录无需逐个删除。确认不再需要展示的终态任务，点「归档」即可；需要原证据时从「已归档」找回。

## 纯 Web：接入一次，在工作记录继续

1. 点「新建任务」直接进入工作记录里的输入区，写下完整目标、资料位置与交付要求，选择账号与本轮模型。不再弹出另一套新建表单；发送前不创建网页。名称和目录可以不填；如需选择已有项目、访问范围、预算或协作方式，展开同页的「项目与运行设置」。留空目录时，发送后在系统「文档/CLW/Tasks」创建独立工作区，不沿用当前数学或游戏目录，也不写入 CLW 源码库。
2. 点击「发送」：程序核对网页实际模型，接入与首轮要求只发一条消息。有完整研究/开发要求可选 Pro；仅接入、没有要求时选极高，不消耗 Pro。展开「发送前查看附加内容」可看连接器（A 为 @Local-MCP，B 为 @Local-MCP-B）、项目背景、用户授权、接入步骤、你的要求及故障约定；自动目录和凭据在发送前使用占位符。新页面加载最多等待 30 秒；登录或就绪检查未通过时保留内容和选项，不重复创建或发送。首轮取得本对话工具身份和资源准入后即可读取、开发、验证和分工，不再要求第二次发送相同目标。
3. 在工作记录查看原任务进展和成果。主控创建 worker 时附上完整首任务，子对话也合并接入与执行；原任务不重复派发。主控让出等待后由程序收集子结果并接续同一请求，无需手动粘贴结果或发“继续”。旧子页若一直尚未发送，主控可补完整合同沿原页面启动；已发送或执行未知的页面先核对原回执。只有后续新目标才再发送。

完整子任务不填权限时继承主控已授权范围在子目录中的部分，无需再次授权；需要只读审查时明确选只读。目录在主控范围之外则仍需明确设置。既有只读任务和已发送消息不追溯改变。首次提示只附必要接入步骤和授权，额外手册按需读取；当前加载状态看 CURRENT。
4. 暂停时，输入框补充只保存在本地；要继续须明确恢复。需更多次数或时间，使用原任务「续杯」，不用新开对话。保存续杯不发送消息、不解除暂停。最终收尾已结束但原目标因attention未结时，核对原回执后续杯并明确「恢复」，接续同一原请求；原运行已closed则用「继续原任务」开始关联原成果的下一运行。详见[续杯合同](MANAGED_WEB.md#给已有任务续杯)。
5. 维护前先「暂停全队」并等原执行停稳；已有成果和原身份保留。任务不会因启动应用自动恢复；数学等具体项目的当前状态看 CURRENT。

子任务显示「等待工作目录空闲 · 尚未发送」时，程序等待主控或其他写者让出目录，不消耗模型发送。若旧任务显示「已接入 · 首任务等待恢复」，表示首条网页消息曾经送达，但实际工作尚未取得执行资格；核对原回执后在原任务恢复，保留原Session和工作包，不重新接入。主控等待真实工作结果后自动回收。此修复的实际加载状态见 CURRENT。

「查看首次发送的完整内容」保留实际首条消息，不会用后来修改的草稿替代历史。A/B 两边取得本对话工具身份后，均可展开「本对话的工具活动」，查看近期工具名称、调用结果和耗时；超过 12 次折叠展示。它是有限日志窗口，不包含所有历史参数/文件差异。Codex＋Web 的任务详情另有按原回合关联的原生工具活动；共享入口日志不能冒充某个任务的调用。

若旧任务提示“接入和简单准备不能使用 Pro”，且仍是“尚未发送”，这是已修正的 CLW 本地规则冲突，不是账号额度或平台安全判断。有首轮研究/方案要求时，加载新版后在原任务点「恢复」即可核对原记录；无需重新建任务，旧错误与消息不会伪装成已发送。实际已发送或发送未知的回合仍先核对原回执。

两种模式共用查看方式，不混用执行身份：纯 Web 在本页输入目标，Codex＋Web 在原 Codex 发送目标和补充。新建任务与已有任务采用统一的模型菜单，选中有勾；模型提示和主动作同步更新，选择本身不发送消息。

接入后的工作回合遇到网页明确的「思考失败 / Thinking failed」，CLW 会保留原任务、结果与工具身份，按 15、45、120 秒退避自动接续，最多三次，计入本任务发送预算。状态栏显示等待恢复或恢复次数用尽。页面慢、最小化或服务重启不会仅因错过两分钟而取消恢复。长时间思考不算失败；暂停、额度限制、登录失效、平台拒绝及发送状态不明不会触发自动“继续”。首次接入还未取得工具身份时，仍需核对接入回执。

已经在外部 Edge 手动工作的原对话，可另选 [Companion 的原页监护与本地程序控制](../../apps/web-recovery-companion/README.md)，支持保留当前 Pro，不迁移对话或要求 CLW 登记。加载并配对扩展后，可在原页启用，也可由 Codex／Claude Code 沿同一 CLI 控制；AB 在线本身不代表网页已被监护。连接等待且公开进度三分钟不变时按已批准规则有限刷新原页，再核真实状态；仍生成继续等，明确终止失败才短接续，断网、人工输入或发送未知时不补发。具体条件与次数只维护在组件说明。此入口与原登记任务载体互斥，真实装载与恢复验收看 CURRENT。

新版网页可能把「无法思考」仅显示在思考状态栏，既没有错误框也没有最终回答。CLW 按最新消息的状态栏识别，并在刷新后核对原消息的唯一标记；不会拿历史回答里的同一句话触发恢复。合并首任务已取得真实 Session 和 request/claim 时，也使用同一退避预算接续，不重新接入；尚无工具身份或执行归属不明时显示具体停点。

### 清理已关闭任务

「已关闭」→「删除本机记录…」→ 确认，可从 CLW 列表永久移除。重启不会重新出现；项目文件、成果和执行回执保留。未结束工作、待核对提交或网页草稿须先处理，删除不是取消执行。

若也要删除 ChatGPT 原对话，先点击「重新打开网页」，在该账号原网页菜单中删除对话，再关闭并删除本机记录。目前没有一键同时删除云端对话的功能；不要把本机删除当作云端已删除。

## 遇到停点怎么办

| 提示 | 你可以做什么 |
|---|---|
| 未登录／连接未就绪 | 从账号与连接进入原账号登录；页面正常后做一次连接检查。检查不调用模型 |
| 尚未发送 | 核对页面和本地队列；不要另建相同目标。纯 Web 可撤回未发送内容到输入框 |
| 已送达但没有结果／原执行待核对 | 打开对应原网页，保留原任务、回执和已有文件；先核对，不重复发送 |
| 工具失败或平台拒绝 | 看原始错误与已完成部分；不是所有失败都能靠“继续”恢复，不换身份重复被拒动作 |
| 模型额度受限 | 保留原任务和模型，等待恢复；本地发送数不能推算官方剩余额度 |
| 退出仍待核对 | 查看具体网页、原生工具或Job及原操作；当前工作结束后核对原退出，不停止或重发未知执行。程序控制可用 `exit-status` 和原 `exit_id` 的 `reconcile-exit` |
| 历史Job很多／预算最终收尾后暂停 | 完成历史数量本身不永久挡住退出或接续；程序仍核对原Session全部活跃状态及未知结果。预算不足时在原任务续杯，再明确恢复；维护暂停仍走「恢复全队」 |

需要维护时提供任务、账号、发生时间、原操作编号或日志和具体错误即可。不要发送 Cookie、访问令牌或隧道密钥。最新已知问题看 [CURRENT](../../CURRENT.md)，工具细节见 [Codex＋Web](../../apps/codex-web-bridge/README.md) 和 [纯 Web](MANAGED_WEB.md)。

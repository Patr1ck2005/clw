# 恢复当前 Web 任务，而不是重新执行

自动恢复只针对绑定网页明确出现的“无法思考/生成失败”。没有输出、长时间思考、Host 接收提示成功，都不等于模型失败。

收到 `recovery_...` 续接提示后，先按提示执行 `harness_host_client.py recover`。该操作经原本机进程权限读取原请求和领取信息，确认本次恢复；不是新权限，不创建任务，不运行 Codex，也不重放 Job。

1. 核对原 project、root、store、target、Session、request 及 `cancel_requested`。用户新的消息和停止优先。
2. `original_claim_id` 不为空时只恢复它；不能生成第二份 claim 或重新派发原工作。先核原 Job、Git 差异和已有产物。原Job仍在运行就接着观察。
3. 从未领取的 queued 请求才用一个固定 claim-id 正常领取。此后按 `HOST_RECEIVER.md` 开发、发布进展/结果。不能将恢复确认当作工作完成。
4. 有子分支时先查原分支与结果；不把等待子任务当作模型失败，不重新生成孩子。

恢复提示最多每个原请求3次，间隔15/45/120秒；每个独立错误只对应一份发送记录。发送结果未知不再点击或换键补发；等原回执或人工核对。草稿、正在生成、页面后台/布局不识别时暂停；用户停止、新消息、登录、额度或安全拒绝中止自动恢复，不绕过。

浏览器伴侣只观察绑定标签页的极少量可见状态并通过普通输入框提交固定提示。不读Cookie/账号密钥、不监听私有模型API、不抓取全部聊天。当前接口没有官方完整模型终态信号，网页适配必须单独实测；页面结构变化应停在 `unsupported`，不能使用模糊按钮继续点击。

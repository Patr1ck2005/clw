# CLW 经验摘要

只收录可复用结论；实验过程保留原证据，不把推测写成产品规则。

整体架构、故障机制和学习顺序见[2026-10-28架构复盘](../ARCHITECTURE_REVIEW.md)。本页保留早期经验出处，当前技术判断优先阅读该复盘。

| 经验 | 证据与实际含义 |
|---|---|
| 连接可用、网页送达、工具执行、成果验收是不同层 | A 连接核验已通过，但 DEMO-02 随后在 user turn 身份比较处失败。修好连接不能代表整个开发稳定。[连接记录](../../evidence/CONNECTOR-FOCUS-20260928/REPORT.md) |
| 后台页面的“已聚焦”不保证收到键盘输入 | 精确复现零字符输入；复用原生编辑命令和精确菜单选择修复，保留选中/清空回读。无需模型测试即可验证 |
| 渲染文本不能直接充当发送正文 | DEMO-02 的连接器布局与富文本转义曾误触发身份保护；按实测结构还原后逐字核对，不能整体去空白或弱化回合归属。[修复记录](../../evidence/DEMO02-SUBMISSION-20260928/REPORT.md) |
| 明确工具错误应查执行环境 | Runner 找不到 rg 曾让带 glob 的搜索失败；补既有工具路径后真实查询通过。这与平台拒绝无关。[搜索修复](../../evidence/MCP-SEARCH-20260927/REPORT.md) |
| 不能从偶然通过推断提示词或授权声明治好了安全拒绝 | 声明准确表达用户授权并自动复用；平台内部原因仍未知。授权不改变真实权限、项目禁令或旧停点 |
| 历史失败回执不能覆盖后来已验证的成果 | camp 手动 CORE 有实现与离线验证；TENET CORE-01 由原主控验收；仍保留旧断流事实。调度成功不等于研究正确，结束回合不等于开发验收 |
| 接续必须核对同一任务 | CLI reconnect 次数不等于网页 Send 次数；已接受/未知操作查原请求、工具回执和磁盘，不另派重做 |
| 复用上游要能重建，不只复制代码 | 固定版本、许可证、CLW 增量与逐文件哈希共同维护；上游升级不能被宣称为平台拒绝通解 |
| 节省额度来自完整工作包和程序等待 | Pro 承载必要实质工作；轻量测试用 Extra High；无新事件不唤醒。原生完成回调尚未接通，就明确说明，不能用模型循环查询代替 |
| UI 的任务与回合必须分层 | 总览聚合任务，详情显示回合，历史折叠；归档只改变展示，不伪造终态或清理执行身份 |

账号、模型、权限、VPN 和原执行身份是稳定边界；具体页面选择器、恢复实现和工具能力随证据更新。新故障先区分发送/页面、身份/桥接、工具执行/回传、平台拒绝，缺证据保留未知。详细历史：[归档入口](history/20260928-before-consolidation/README.md)。
